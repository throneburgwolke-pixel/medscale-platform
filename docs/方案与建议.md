# 医学量表与问卷平台 · 方案与建议

> 面向临床科研场景设计：**量表可直接调用 → 问卷可自制 → 扫码发放 → 自动回收 → 自动计分 → 一键统计导出**。
> 本文档同时说明已实现的系统（本目录同级 `medscale/`）与后续可选迭代方向。

---

## 四、技术方案与选型说明

### 4.1 技术栈（刻意选择"零依赖"）

| 项目 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js（内置 `node:http`、`node:sqlite`、`node:zlib`） | **不需要联网安装任何第三方包**，没有供应链风险，医院内网也能部署 |
| 数据库 | SQLite 单文件（`data/app.db`） | 备份＝复制一个文件；无需安装数据库服务 |
| 前端 | 原生 HTML/CSS/JavaScript 单页应用 | 无构建步骤，双击即用，后续任何程序员都能接手 |
| 二维码 | 自研编码器（字节模式 + Reed-Solomon 纠错） | 不依赖外部 API，断网可用；已与标准实现逐模块比对一致 |

### 4.2 为什么不用现成的在线问卷平台？

| 维度 | 通用问卷平台 | 本平台 |
|---|---|---|
| 数据主权 | 数据存放在第三方服务器 | 数据留在本院/本机 |
| 量表版权 | 平台方不承担授权责任 | 每个量表标注授权来源，可自查 |
| 计分能力 | 反向计分/维度分/分级常需付费版 | 原生支持反向计分、维度、分级判读 |
| 统计能力 | 一般只给频数 | 直接输出 α、CITC、t 检验、ANOVA、χ² |
| 费用 | 按份数/年计费 | 一次性部署，无后续费用 |
| 合规 | 涉及个人信息出境/第三方处理 | 可完全内网运行 |

### 4.3 三种部署方式（按需选择）

| 方式 | 适用场景 | 优点 | 注意 |
|---|---|---|---|
| **A. 本机 / 局域网**（推荐起步） | 门诊、病房、科室内发放 | 数据不出内网，最安全；手机连同一 WiFi 即可扫码填写 | 电脑需开机；跨院区无法访问 |
| **B. 院内服务器** | 多科室长期使用 | 稳定、可多人协作、便于统一备份 | 需信息科开放端口，建议配 HTTPS 与统一身份认证 |
| **C. 云服务器 + 域名 + HTTPS** | 面向院外患者/多中心研究 | 随时随地填写，可大规模发放 | 必须做等保/数据安全评估，建议匿名化并取得伦理批准 |

启动方式（任何方式都一样）：

```bash
cd medscale
node server.js          # 默认 http://localhost:5173
PORT=8080 node server.js   # 换端口
```

macOS 可直接双击 `medscale/启动平台.command`。

## 五、量表版权与伦理合规（建议重点阅读）

### 5.1 量表授权是科研中最容易被忽视的风险点

已内置模板的授权状态已在系统中逐条标注，摘要如下：

| 量表 | 授权要点 |
|---|---|
| PHQ-9 / GAD-7 / PHQ-15 | Pfizer 声明可免费使用、复制、翻译、分发，建议引用原始文献 |
| ISI、WHO-5、PSS-10、PSQI、ESS | 学术/非商业研究一般可免费使用，需规范引用（ESS 商业使用需 Mapi 授权） |
| NRS 疼痛评分 | 通用临床工具，无特殊限制 |

**未内置条目文本（需授权/培训）**：

| 量表 | 要求 |
|---|---|
| MMSE | 受版权保护（PAR 公司），需购买或授权 |
| MoCA | 需完成官方培训并取得认证账号 |
| HADS | GL Assessment 管理版权，需申请授权 |
| SF-36 / SF-12 | 需通过 QualityMetric 或授权机构获取 |
| EORTC QLQ-C30 | 需向 EORTC 申请使用许可（学术用途通常可免费注册） |

> 建议：投稿前逐条核对授权条款，并在论文"方法"部分写明量表版本、计分方式与授权情况。

### 5.2 伦理与知情同意

开展涉及患者的研究前需要：

1. **伦理审查批件**（即使只是匿名问卷，多数医院也要求"免除知情同意"的伦理审批）
2. **知情同意**：本平台支持在问卷前强制展示同意文本并勾选留痕（答卷中记录"是否同意=是"）
3. **隐私最小化**：默认匿名；确需随访时才收集姓名/住院号，并单独说明用途与保存期限
4. **数据可追溯**：每条答卷都有编号与提交时间；如做随访需保留被试编号对照表，且对照表应与数据分开保存

### 5.3 论文报告规范（建议）

- 观察性研究遵循 **STROBE** 声明；问卷研究建议同时报告回收率、有效应答率、缺失值处理方式
- 报告中需给出：量表来源文献、计分规则、**本研究样本的 Cronbach's α**、样本特征描述
- 若自行删改量表条目，须说明理由并重新验证信效度（不能直接沿用原量表的 α）

## 六、统计方法建议（平台能力与后续分析边界）

### 6.1 信度与效度：论文里几乎必查

| 指标 | 何时报告 | 判断标准 |
|---|---|---|
| Cronbach's α | 维度内条目 ≥2 且为求和/均分时 | ≥0.9 优秀；0.8–0.9 良好；0.7–0.8 可接受；<0.7 需修改条目 |
| CITC（校正题总相关） | 项目分析 | <0.3 提示该题区分度不足，考虑删除 |
| 分半信度 | 样本量足够时作为补充 | 建议与 α 一并报告 |
| 重测信度 | 需同一批人两次测量 | ICC ≥0.75 较好（需自建配对数据，平台暂不自动计算） |
| 结构效度 | 自制量表 | 需 EFA（探索性因子分析）与 CFA（验证性因子分析），建议导出数据后用 R/SPSS/AMOS 完成 |
| 内容效度 | 自制量表 | 需专家评议，计算 CVI（内容效度指数） |

### 6.2 样本量

- **经验法则**：量表条目数的 10–20 倍（如 20 题量表建议 200–400 例）
- **做因子分析**：建议 ≥5–10 倍条目数，且不少于 200 例
- **组间比较**：先估算效应量，用 G*Power 计算（两组 t 检验、中等效应量、α=0.05、power=0.8 通常约需每组 64 例）
- **建议**：发布时设置"目标样本量"，本平台会在达到上限后自动停止回收

### 6.3 缺失值处理

平台会统计每题缺失数与缺失率：

- 缺失率 <5%：可考虑**整例删除**（平台的信度分析已自动只使用完整作答案例）
- 缺失率 5%–20%：考虑**多重插补（MI）**，不要用均值填补（会低估方差）
- 维度缺失：部分量表允许按"维度均分×条目数"折算（需在方案中预先说明）
- 关键条目缺失（如 PHQ-9 第 9 题）：不应填补，建议单独分析

### 6.4 常用检验选择

| 研究问题 | 数据条件 | 推荐方法 |
|---|---|---|
| 两组间得分差异 | 计量、近似正态、方差齐 | 独立样本 t 检验（平台用 Welch 校正，更稳健） |
| 三组及以上 | 计量、近似正态 | 单因素方差分析（平台附 η² 效应量；显著后需事后两两比较） |
| 等级/偏态分布 | 有序分类或严重偏态 | Mann-Whitney U / Kruskal-Wallis（建议导出数据后完成） |
| 率/构成比比较 | 分类变量 | 卡方检验（平台已给出理论频数<5 的警告，此时应用 Fisher 精确检验） |
| 两变量关系 | 连续或等级 | Pearson / Spearman 相关（平台同时输出 p 值与样本量） |
| 影响因素筛选 | 多因素 | 多重线性回归 / Logistic 回归（导出后完成） |
| 一致性 | 两次测量/两位评估者 | ICC、Kappa |

> **平台定位**：把数据整理、计分、描述统计、信度与基础差异检验全部自动化，**复杂建模（回归、因子分析、生存分析、混合模型）导出数据后在 SPSS/R/Stata 中完成**——这样既省去最耗时的整理工作，又保留统计方法的灵活性。

## 七、数据安全与合规清单

| 措施 | 本平台现状 | 建议 |
|---|---|---|
| 数据本地化 | 全部数据在 `data/app.db`，无外发 | 存放在专用电脑或院内服务器的加密磁盘 |
| 访问控制 | 管理员密码登录（会话 14 天） | 修改默认密码；多人使用建议每人单独账号（见迭代方向） |
| 匿名化 | 支持匿名模式，答卷仅有随机编号 | 涉及敏感信息时开启匿名并关闭 IP 采集 |
| 传输加密 | HTTP（本机/内网） | 公网部署必须配 HTTPS（Nginx/Caddy 反向代理） |
| 备份 | 单文件数据库 | **每周复制 `app.db` 到移动硬盘/院内网盘**；导出 CSV/JSON 作为二次备份 |
| 操作留痕 | 记录登录、发布、导出、删改等操作日志 | 定期导出日志备查 |
| 数据销毁 | 删除调查会同时删除其答卷 | 研究结束后按伦理要求定期销毁，并保留销毁记录 |
| 最小必要 | 默认不采集姓名、住院号等身份信息 | 确需身份信息时，另建编号对照表并分开保存 |

## 八、迭代路线图（下一阶段可选）

### 第一优先（投入小、收益大）

1. **多用户与权限**：管理员 / 研究者 / 只读三种角色，每人独立账号与操作日志
2. **跳题逻辑**（如"无月经者跳过第 4 题"）与**随机化选项顺序**（减少应答偏倚）
3. **重复提交识别**：同一设备/同一编号 24 小时内重复提交提示
4. **SPSS 直接可用导出**：`.sav` 或"数值编码版 CSV"（选项导出为 0/1/2 而非文字）
5. **结果报告一键生成 Word/PDF**：把统计表与图表套入论文模板

### 第二优先（面向长期使用）

6. **随访功能**：多次测量（基线/1 个月/3 个月）与配对 t 检验、重复测量方差分析
7. **量表版本管理**：同一量表修改留痕，历史答卷仍对应旧版本计分
8. **多中心协作**：各分中心单独链接、单独回收进度，数据统一汇总
9. **微信生态**：小程序或公众号内嵌填写，提高回收率
10. **数据可视化看板**：按日回收曲线、按科室筛选

### 需要外部条件的

11. 结构方程/因子分析内置（建议直接导出数据用 R/lavaan 完成，性价比更高）
12. 与医院 HIS/电子病历对接（需信息科支持）

## 一、需求拆解：把"五步割裂"变成"一条流水线"

临床科研中量表使用的典型痛点：

| 环节 | 传统做法 | 主要问题 |
|---|---|---|
| 找量表 | 翻论文、翻书、找同事要 Word | 版本混乱，条目/选项分值容易抄错 |
| 做问卷 | Word / Excel 打印，或第三方问卷平台手敲 | 题干录入易错；第三方平台计分规则受限 |
| 发放 | 纸质发放、纸质回收 | 回收率低，人工录入耗时且易错 |
| 回收 | 纸质、Excel 手工录入 | 缺失值、跳项、录入错误难追溯 |
| 计分 | 手工加总、Excel 公式 | 反向计分、维度分、分级判读极易出错 |
| 统计 | 再导入 SPSS/R | 重复劳动，且常忘记做信度与项目分析 |

**解决思路**：把"量表定义（题目+选项+计分规则）"变成结构化数据，之后所有环节都由系统自动完成——
定义一次，扫码即收，收完即算。

### 3.2 问卷编辑器（自制问卷/量表）

- **9 种题型**：单选、多选、下拉、数字、滑块、单行/多行填空、时间、日期
- **计分设置**：求和 / 均分 / 不计分；总分倍数（如 WHO-5 ×4）；反向计分
- **"不计入总分"开关**：解决"性别、年龄等人口学题被算进总分"的常见错误
- **维度设置**：多维度量表自动输出各维度小分
- **分级解释**：自定义区间（≤ 分值 → 判读 → 处理建议），提交后自动判读
- **知情同意**：可强制填写前阅读并勾选，留痕记录
- **预览**：保存前先看受试者手机上的真实效果
- **顺序调整 / 复制题目 / 快速添加 5 道李克特题**

### 3.3 发放与回收

- 一键生成**专属链接 + 二维码**（二维码离线生成，不依赖任何第三方服务）
- 手机端自适应页面，分页作答（每 10 题一页）+ 进度条 + 必答校验
- 可选：样本量上限、截止日期、匿名模式、是否采集 IP/设备、提交后是否向受试者展示结果
- 关闭后自动停止回收，链接显示"已关闭"

### 3.4 自动计分与统计分析

| 类别 | 已实现 |
|---|---|
| 描述统计 | n、均值、标准差、标准误、中位数、P25/P75、IQR、最小/最大、偏度、峰度、95% 置信区间 |
| 频数统计 | 每个选项的频数与占比；缺失值及缺失率 |
| 总分与维度 | 各维度分、总分、分级人数与占比分布 |
| 信度 | Cronbach's α（总分与各维度）、分半信度（Spearman-Brown）、CITC 校正题总相关、删除该题后的 α |
| 相关分析 | 维度间/维度与总分的 Pearson r 与 p 值矩阵 |
| 组间比较 | 按分类变量（性别、学历等）自动做独立样本 t 检验（Welch）或单因素方差分析（含 η²、Cohen's d） |
| 交叉分析 | 严重程度分级 × 分组变量的卡方检验（含 Cramér's V 与理论频数<5 警告） |
| 安全预警 | PHQ-9 第 9 题等关键条目阳性人数与占比 |
| 图表 | 总分分布直方图（含均值线）、分级分布柱状图、维度均值±标准差柱状图、任选题目的作答分布 |
| 导出 | CSV（UTF-8 含 BOM，Excel 直接打开；选项自动转成文字标签）、JSON（含原始数据+完整报告，便于复核与再分析） |

统计结论已与标准临界值表交叉验证（t 分布、F 分布、χ² 分布的 p 值均与教科书分位数一致）。

- 管理员密码登录（首次启动自动生成 16 位随机初始口令，见启动日志或数据目录的「管理员初始口令.txt」，登录后请立即修改）
- 数据全部保存在本机 `medscale/data/app.db`（SQLite），**不经过任何第三方服务器**
- 内置量表只读保护（须"创建副本"后再改），已发布调查的量表禁止删除，避免误删数据
